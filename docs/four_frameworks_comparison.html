6️⃣ 优缺点并列对比

🟣 Drogon 优点

  • ✅ 性能最强 (162K QPS)
  • ✅ 非阻塞事件驱动 I/O
  • ✅ C++20 协程支持
  • ✅ HTTP/2 支持
  • ✅ 内置 ORM/JSON/过滤器
  • ✅ WS 不占线程
  • ✅ 高并发扩展性极好
  • ✅ 活跃社区维护

Drogon 缺点

  • ❌ 重框架 (1.9MB + 多依赖)
  • ❌ 与 Qt EventLoop 集成困难
  • ❌ 学习曲线陡峭
  • ❌ 迁移成本极高 (全盘重写)
  • ❌ 对于局域网共享大材小用
  • ❌ 侵入性强

🔵 cpp-httplib 优点

  • ✅ 单头文件 header-only
  • ✅ 集成成本为零
  • ✅ 现代 C++11 lambda API
  • ✅ MIT 许可
  • ✅ HTTP/HTTPS/WS/SSE/流式
  • ✅ 路径参数路由
  • ✅ 三种 SSL 后端可切换
  • ✅ 内存最小 (1.3MB)

cpp-httplib 缺点

  • ❌ 不支持 32 位
  • ❌ 阻塞 I/O, QPS 仅 91
  • ❌ 每个 WS 独占一线程
  • ❌ 不支持 HTTP/2
  • ❌ 高并发性能差
  • ❌ 不适合万级并发

🔴 cpprestsdk 优点

  • ✅ 微软官方项目, 文档完善
  • ✅ 异步 PPL Tasks API
  • ✅ HTTP 客户端/服务器双端
  • ✅ WebSocket 客户端/服务器
  • ✅ 内置 JSON 和 OAuth 支持
  • ✅ 跨平台: Win/Linux/macOS/iOS/Android
  • ✅ 支持 CMake/vcpkg 安装

cpprestsdk 缺点

  • ❌ ⛔ 维护模式, 停止新功能
  • ❌ 依赖 Boost.Asio (重量级)
  • ❌ 无 Range/断点续传
  • ❌ 无静态文件服务
  • ❌ 无中间件/过滤器机制
  • ❌ 无 SSE 支持
  • ❌ 编译和部署较复杂
  • ❌ 建议新项目不要使用

🟢 CivetWeb 优点

  • ✅ MIT 许可
  • ✅ 零外部依赖
  • ✅ HTTP/HTTPS/WS/文件服务
  • ✅ 成熟稳定 10+ 年
  • ✅ 跨平台 32/64 位
  • ✅ 资源占用低 (~2-4MB)
  • ✅ 与 Qt 兼容性最佳

CivetWeb 缺点

  • ❌ C API, 需 C++ 封装层
  • ❌ 线程模型僵化
  • ❌ 不支持 HTTP/2, SSE
  • ❌ 无高级路由功能
  • ❌ 无 REST 客户端
  • ❌ 性能天花板较低
  • ❌ 维护活跃度下降
